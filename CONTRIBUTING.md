# Contributing

Thanks for wanting to help. Issues, questions and pull requests are welcome.

## Questions

Use **Discussions → Q&A** instead of opening an issue. If an answer solves it, click **Mark as answer** so the next person finds it.

## Bugs and ideas

Open an issue with what you expected, what happened and how to reproduce it.

## Pull requests

1. Fork the repo and create a branch from `main`.
2. Keep the change focused: one fix or feature per PR.
3. Describe what changed and why. Link the issue if there is one (`Closes #12`).
4. Make sure the project still builds before opening the PR.

## Pairing and co-authorship

If we wrote the code together, credit everyone who took part. End the commit message with a blank line and one trailer per co-author, using an email registered on their GitHub account (or their `ID+user@users.noreply.github.com` address):

```
fix: player collision on slopes

Co-authored-by: Name <email@example.com>
```

Only credit people who actually worked on the change.
